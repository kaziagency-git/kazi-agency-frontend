Role Definitions & Permissions

🛡️

Admin

Agency Owner / Manager
  • Full access to everything
  • Create & manage user accounts
  • Assign developers to tickets & projects
  • View all KPIs & reports
  • Manage billing & invoices
  • Configure GHL sync & n8n webhooks
  • Override any ticket or milestone
  • Manage canned responses & SLA rules
  • Access knowledge base editor
💻

Developer

Agency Team Member
  • View & update assigned tickets only
  • Add internal notes (hidden from client)
  • Request files / info from client
  • Upload deliverable files
  • Mark milestones complete
  • Log work hours per task
  • Chat in ticket threads
  • View own task board & workload
  • Cannot access billing or other clients
👤

Client

Paying Customer
  • Access own project data only
  • Submit new support tickets
  • View ticket status & reply
  • View project progress & milestones
  • Approve or request revision on deliverables
  • Download final assets
  • View invoices & payment status
  • Access knowledge base (read-only)
  • Cannot see internal team notes

Phase 1 — Support Ticket System

Phase 1: Support Tickets

First build — immediate value, replaces GHL's manual support handling

Sprints 1–4  |  Weeks 1–8

Ticket Lifecycle — Status Flow

🆕 Open
→
🔄 In Progress
→
⏳ Waiting Client
→
✅ Resolved
→
🔒 Closed
Re-open path: Client can re-open a Resolved ticket within 7 days. After that, Closed requires Admin action.

Ticket Categories

  • 🐛 Bug / Issue Report
  • ✨ Feature / Change Request
  • ❓ General Question
  • 📦 Delivery / Asset Request
  • 💳 Billing / Invoice
  • 🚀 Onboarding Help

Priority Levels & SLA

  • 🔴 Critical — 2 hour first response
  • 🟠 High — 8 hour first response
  • 🟡 Medium — 24 hour first response
  • 🟢 Low — 48 hour first response
  • ⏰ SLA breach alert to Admin
  • 📊 SLA metrics in admin report

Ticket Thread Flow — Who Does What

Actor Action Notification Sent To
Client Submits ticket with category, priority, description, files Admin (email + in-app) · Auto-assign dev notified
System Auto-assigns developer based on category rules, sends Ticket ID + ETA to client Client (email confirmation)
Developer Updates status → In Progress, adds internal notes Admin sees status change
Developer Requests info or files from client (status → Waiting Client) Client (email + in-app)
Client Replies in thread, uploads requested file Developer + Admin (in-app)
Developer Marks ticket Resolved with resolution summary Client (email + in-app)
Client Confirms or re-opens within 7 days Developer + Admin
Admin Can override status, reassign, or escalate at any point Relevant party notified

Phase 3 — GHL Migration Plan

Phase 3: GHL → Own Platform Migration

Progressive feature migration — keep GHL alive until each module is stable on your platform

Month 6 → Month 18

🔴 Priority 1 — Migrate First

Easiest ROI, low complexity

  • Contact / CRM database
  • Pipeline stage tracking
  • Email notifications (Resend)
  • Intake / lead capture forms

🟡 Priority 2 — Moderate

Moderate complexity, high value

  • Two-way messaging (SMS + email)
  • Appointment booking system
  • Review / reputation management
  • Automated follow-up sequences

🟢 Priority 3 — Keep GHL Longest

Complex — only migrate when P1+P2 stable

  • Automation / workflow builder
  • Advanced reporting dashboards
  • Social media scheduling
  • Funnel / page builder

n8n Integration Bridge Strategy

During the entire migration period, keep n8n as the automation glue. Add webhook endpoints to your Next.js API that n8n can trigger — so GHL, your dashboard, and external services all communicate through n8n without breaking existing workflows. Gradually shift automation logic to native Next.js API routes only after each GHL module is fully migrated and stable.

Why Supabase as the core data layer?

Supabase gives you PostgreSQL (full relational DB for tickets, projects, clients), Realtime subscriptions (live thread updates without polling), Storage (secure file uploads with access control), and Row Level Security (database-enforced role isolation — a client literally cannot query another client's rows). It pairs perfectly with Next.js and eliminates the need for separate services for DB, storage, and real-time in Phase 1.
